# Clata Data Model

SQLite is the local source of truth. Derived tables are rebuildable caches.

## Source data

- `app_metadata`: schema version, device ID, install state.
- `installed_packages`: package identity, version, source, install state, archive reference.
- `package_archives`: original signed archive metadata for export; content path is private app storage.
- `units`, `words`, `sentences`, `dialogues`, `challenges`: immutable installed content keyed by `package_id` and item ID.
- `learning_events`: append-only source events.
- `settings`: local settings with per-key update time.
- `settings` keys `birth_year`, `age_gate_status`, `selected_package_id`, `intro_dismissed`, and `local_data_warning_acknowledged` are local-only onboarding/profile state.
- `challenge_checks`: local-only `Sudah kucoba` state.
- `practice_sessions` and `practice_questions`: durable session/question snapshots; these are operational state and are not the source of mastery truth.
- `sync_outbox`, `sync_state`, `reset_commands`: P1 synchronization state.

## Derived data

`item_strength_cache`, `dialogue_scores`, `active_days`, `highest_levels`, and `statistics_cache` MUST be rebuildable from source events and installed content.

## Invariants

- Progress identity is `(package_id, item_id)`.
- Event identity is a globally unique ULID generated by the device.
- Normal operations never update or delete learning events.
- Challenge checks never create learning events.
- Practice question snapshots never replace `learning_events` as the source of progress truth.
- Removing a package removes content and archive but not progress events.
- Reset uses an explicit reset command/tombstone so older events cannot resurrect progress during sync.
- Delete-all-data requires a second confirmation and removes source plus derived data.

## Replay

Replay orders events by trusted normalized event time, then `event_id`. Every answer event stores `formula_version`. Strength, mastery, streak, statistics, and level are recomputed after merge, migration, or package update.

## Migration

Migrations are forward-only, numbered, transactional, and tested from every supported release. A failed migration rolls back. A backup/snapshot is created before risky migrations. No migration may discard learning events silently.
