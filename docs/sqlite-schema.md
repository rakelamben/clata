# Clata SQLite Schema Contract

This document defines the implementation contract; exact SQL may be generated by the selected SQLite adapter.

## Required identity rules

- IDs are opaque text; package/item IDs are stable and case-sensitive.
- `installed_packages(package_id)` is the package identity; `(package_id, item_id)` is the item key.
- Foreign keys MUST be enabled.
- All timestamps are ISO-8601 UTC; `local_date` is `YYYY-MM-DD` from the device timezone at event creation.

## Core tables

| Table | Required key/index |
|---|---|
| `app_metadata` | singleton key; schema version index |
| `installed_packages` | PK `package_id`; unique `(package_id, package_version)`; state index |
| `package_installations` | PK `installation_id`; package/state/commit-marker indexes |
| `package_archives` | PK `(package_id, package_version)`; checksum unique; active archive FK |
| `units` | PK `(package_id, unit_id)`; order index |
| `staged_units`, `staged_words`, `staged_sentences`, `staged_dialogues`, `staged_challenges` | PK `(installation_id, item_id)`; installation index |
| `dialogue_graph_snapshots` | PK `(package_id, package_version, dialogue_id, graph_fingerprint)`; immutable |
| `staged_dialogue_graph_snapshots` | PK `(installation_id, package_version, dialogue_id, graph_fingerprint)` |
| content tables | PK `(package_id, item_id)`; unit/register indexes |
| `learning_events` | PK `event_id`; `(package_id, item_id, event_type)` and sync indexes |
| `app_event_sequence` | singleton allocator row; next-sequence constraint |
| `sync_outbox` | PK `outbox_id`; nullable `event_id`/`command_id`; unique idempotency key; status/retry indexes |
| `sync_state` | account/device scope unique; cursor index |
| `reset_commands` | PK command ID; package/status/boundary index |
| `package_reset_boundaries` | PK `package_id`; local-sequence boundary index |
| `active_day_package_words` | PK `(local_date, package_id, item_id)` |
| `package_item_introductions` | PK `(package_id, package_version, item_id, item_type)`; fingerprint/package indexes |
| derived tables | composite package/item keys and rebuild marker |

## Event contract

`event_id`, `device_id`, `package_id`, nullable `item_id`, `event_type`, `source`, `result`, `weight`, `session_id`, `device_time`, `received_time`, `local_date`, `formula_version`, `payload_json`, `sync_status`.

Payload schemas are event-type-specific and MUST be validated before insert. Unknown event types are rejected, not ignored.

## Transaction rules

Event insert, account-bound outbox insert, and cache invalidation happen in one transaction. Local reset commands also create a durable null-account outbox row. Package install writes to staging tables/storage and activates metadata only after validation succeeds. Versioned archive metadata is retained by `(package_id, package_version)`.
